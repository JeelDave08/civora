                     CIVORA SMART CITY PLATFORM - SYSTEM FLOW & ARCHITECTURE
================================================================================

1. PROJECT OVERVIEW & ARCHITECTURE
--------------------------------------------------------------------------------
CIVORA is a state-of-the-art, full-stack Smart City Civic Management Platform designed to streamline civic issue reporting, automated triage, field agent dispatch, real-time work tracking, AI-assisted verification, and community engagement.

The architecture comprises:
  • Frontend: React 18 with TypeScript, Vite, Tailwind CSS, Lucide Icons, Leaflet Maps, and TanStack React Query.
  • Backend: Node.js with Express.js REST API.
  • Database: MongoDB with Mongoose ODM (Databases & Collections: civora).
  • Security & Auth: JSON Web Tokens (JWT), Bcrypt password hashing, domain-restricted admin authentication, and multi-collection user lookup.
  • AI Integration: Dual Vision AI Pipeline (OpenAI GPT-4o Vision API with automatic fallback to Google Gemini 3.6 Flash Vision API) for automatic issue category detection, severity rating, and department routing.
  • Geospatial Engine: MongoDB 2dsphere indexing, Haversine formula distance calculation, and reverse geocoding via LocationIQ & OpenStreetMap Nominatim.
  • Automated Notifications & Emailer: Nodemailer SMTP service for automated personnel credential delivery and persistent database notifications.

3. AUTHENTICATION & SECURITY ARCHITECTURE
================================================================================
1. Multi-Collection Authentication Engine:
   • Endpoint `/api/auth/login`: Accepts credentials (`loginId` and `password`). Sanitizes email input.
   • Sequential Multi-Collection Lookup:
       Step A: Searches `User` collection (Citizens).
       Step B: If not found, searches `Supervisor` collection.
       Step C: If not found, searches `FieldWorker` collection.
       Step D (Fallback): Checks `personalEmail` in `Supervisor` and `FieldWorker` collections.
   • Bcrypt Hash Verification: Validates input password against stored hash using `bcrypt.compare()`.
   • JWT Token Generation: On match, signs a JSON Web Token containing `{ id, role }` using `process.env.JWT_SECRET` with a 24-hour expiration.
   • Audit Logging: Automatically records a `USER_LOGIN` action in `ActivityLog`.

2. Domain-Restricted Administrator Authentication:
   • Endpoint `/api/admin-auth/login`: Specifically requires emails matching the `@admin.civora.com` domain format (e.g., `admin@admin.civora.com`).
   • Generates JWT with payload `{ id, role: 'admin', isAdmin: true }` valid for 8 hours.
   • Updates `lastLogin` timestamp on success.

3. Google SSO / Firebase Authentication:
   • Endpoint `/api/auth/google`: Accepts Google display name, email, and Firebase UID.
   • Checks if user exists in `User` model; if not, automatically provisions a new citizen profile.

4. Frontend Security & Route Guards:
   • `AuthContext.tsx`: Persists JWT token and user profile in `localStorage`. Listens to browser storage events.
   • `ProtectedRoute.tsx`: Intercepts navigation requests. Compares current user role against allowed roles (`admin`, `supervisor`, `worker`, `citizen`).
   • Redirects unauthorized access attempts to `/login` or `/403 Forbidden`.

4. DETAILED ROLE-BASED SYSTEM WORKFLOWS
================================================================================

--------------------------------------------------------------------------------
A. CITIZEN ROLE FLOW
--------------------------------------------------------------------------------
Step 1: Registration & Login
  - Citizen registers with Full Name, Email, Password, City, and optional Phone/Address.
  - Alternately logs in via Google SSO.
  - System issues JWT token and redirects to `/citizen/dashboard`.

Step 2: Citizen Dashboard & Civic Impact Score
  - Real-time KPI summary: Total Submitted, In Progress, Resolved, Pending.
  - Civic Impact Telemetry: Calculates Impact Score (0 to 100%) based on reported complaints, resolution ratio, community verifications, and contributions.
  - Assigns dynamic Civic Tier (e.g., "🌱 Getting Started", "🏙️ Active Citizen", "🌟 Active Civic Contributor", "🏆 High Civic Impact").

Step 3: Raising a Complaint (4-Step Guided Wizard)
  - Step 1 (Category & Priority): Selects category (Road, Waste Management, Water Supply, Electricity, Drainage, Building, Other) and priority level.
  - Step 2 (Description & Title): Inputs detailed issue title and description.
  - Step 3 (Geospatial Location & Evidence Upload):
      • Live GPS Detection: Acquires latitude/longitude via browser Geolocation API and Leaflet map.
      • Reverse Geocoding: Backend proxies GPS coordinates to LocationIQ / Nominatim API to format precise Indian street address.
      • Photo Evidence: Uploads up to 3 evidence images hosted via Cloudinary.
      • AI Vision Analysis: Sends photo URL to `/api/complaints/analyze-image`. AI model classifies detected issue, confidence score, category, and department.
      • Multivariable Duplicate Search: Sends parameters to `/api/complaints/check-duplicates`. If duplicate score >= 30%, prompts citizen to join existing community issue.
  - Step 4 (Submission & Confirmation): Generates unique Complaint Ticket Code (e.g., #CMP-8492). Citizen can confirm or override AI suggestions via `/api/complaints/:id/confirm-ai`.

Step 4: Community Issues & Multi-Citizen Joining
  - Citizens can join existing community complaints (`/api/complaints/:id/join`), upload supplementary evidence photos, and follow for status notifications.

Step 5: Nearby Civic Map
  - Interactive Leaflet map displaying active and resolved complaints with color-coded status markers and real-time distance calculations.

Step 6: Citizen Resolution Verification
  - When field workers complete a repair, nearby citizens receive in-app verification alerts.
  - Citizens vote "Yes, Resolved" or "Still Exists".
  - If "Still Exists" votes reach the system threshold (default 2), system triggers an automatic `Community Reopen Alert`.

Step 7: Gamification & Rewards Redemption
  - Citizens earn reward points for reporting and verifying issues.
  - Accesses Rewards Portal (`/api/citizen/rewards`), spends points to claim municipal vouchers (Free Parking Pass, Transit Pass, City Event Ticket, Property Tax Rebate).
  - System generates unique claim code (e.g., `CIV-PARK-8912`).

Step 8: Profile & Feedback
  - Updates profile avatar, phone number, and address.
  - Submits platform ratings (1 to 5 stars) and feedback reviews.


--------------------------------------------------------------------------------
B. SUPERVISOR ROLE FLOW
--------------------------------------------------------------------------------
Step 1: Department & Ward Authentication
  - Supervisor logs into portal (`/supervisor/dashboard`).
  - Access is scoped to assigned municipal department (e.g., Roads & Infrastructure, Waste Management, Water Supply).

Step 2: Executive Triage Queue
  - Views open complaints filtered by ward, priority, and age.
  - Inspects citizen reported photo evidence gallery, AI vision breakdown, map location, and supporter counts.

Step 3: Worker Dispatch & Task Assignment
  - Selects available field worker from department pool.
  - Sets Scheduled Start Date and Estimated Due Date.
  - Submits assignment (`PUT /api/admin/complaints/:id/assign`), updating status to `Assigned`.

Step 4: Live Execution & Timer Monitoring
  - Tracks live worker status (e.g., "⏱ Working Now" timer active).
  - Reviews cumulative time logged by worker (in minutes and seconds).

Step 5: Resolution Approval & Citizen Verification Trigger
  - When field worker submits completion proof, supervisor inspects "Before & After" photos and execution remarks.
  - Supervisor approves resolution (`POST /api/admin/complaints/:id/approve-resolution`).
  - Approval updates status to `Pending Citizen Verification` and dispatches in-app verification requests to citizens within `verification_radius_km` (default 5 km).

Step 6: Community Reopen Alert Management
  - If community votes trigger a reopen alert (`Community Reopened – Supervisor Review Required`), supervisor reviews community complaints.
  - Action Options: Re-assign task to field worker for rework (`REWORK`) or confirm verified closure (`CLOSE`).

Step 7: Team Monitoring
  - Monitors department field workers, active task counts, resolved task totals, and logged work hours.


--------------------------------------------------------------------------------
C. FIELD WORKER ROLE FLOW
--------------------------------------------------------------------------------
Step 1: Mobile Field Portal Authentication
  - Worker logs into mobile-responsive portal (`/worker/dashboard`).
  - Displays daily task list categorized by priority and due date.

Step 2: Task Execution & Interactive Work Timer
  - Opens assigned task detail page (`/worker/tasks/:id`).
  - Views location address, GPS map, citizen description, and original evidence photos.
  - Interactive Work Timer:
      • Click "Start Work Timer": Calls `/api/admin/complaints/:id/status` with `actionType: 'START_WORK'`. Sets `workStartedAt`, status to `Working`, and `isTimerRunning: true`.
      • Real-time stopwatch counts seconds on worker screen.
      • Click "Stop Timer": Calls `actionType: 'STOP_WORK'`, updating `workEndedAt` and persisting cumulative `timeSpentSeconds` in database.

Step 3: Completion Proof Submission
  - Uploads "After / Repair Proof" photos (Cloudinary hosted).
  - Enters execution remarks detailing work completed.
  - Submits task completion: Updates status to `Pending Citizen Verification` and creates `CitizenVerification` record.


--------------------------------------------------------------------------------
D. ADMIN ROLE FLOW
--------------------------------------------------------------------------------
Step 1: Executive Command Center (`/admin/dashboard`)
  - Overall KPI metrics: Total Complaints, Active Supervisors, Field Workers, Registered Citizens, Resolution Rate %.
  - Timeframe Filter (Last 7, 15, 30, or 60 days).
  - Triage queue for unassigned civic tickets.

Step 2: Ward-Wise Personnel Onboarding & Email Dispatch
  - Creates Supervisors and Field Workers via `/api/admin/personnel`.
  - Onboard with Name, Portal Login Email, Personal Email, Password, Department, and City/Ward.
  - Automated Credential Emailer: Backend uses Nodemailer (`utils/emailSender.js`) to automatically email login credentials and temporary password to the employee's personal email.

Step 3: Civic Intelligence & Problem Heatmap (`/admin/civic-intelligence`)
  - City-wide interactive Leaflet heatmap displaying complaint clusters.
  - Filters by category, status, priority, ward, department, timeframe, SLA breach status, and community issues.
  - Ward Hotspot Aggregation: Ranks top problem wards by active complaint volume.

Step 4: Community Issues & Manual Duplicate Merging (`/admin/complaints/community-issues`)
  - Displays consolidated primary community issues and supporter statistics.
  - Manual Merge Tool (`POST /api/admin/complaints/merge`): Allows admins to merge secondary duplicate complaints into a primary complaint. Consolidates evidence photos and supporter counts, updating status to `Closed` and recording a `COMPLAINT_MERGED` audit log.

Step 5: Department & Service Management (`/admin/services`)
  - Add, edit, toggle status ('Active', 'Maintenance', 'Inactive'), or delete municipal departments.

Step 6: User Access & Password Management (`/admin/citizens`, `/admin/personnel`)
  - Reset user passwords securely for citizens or personnel.
  - Delete user accounts with audit log recording.

Step 7: System Monitoring & Activity Audit Logs (`/admin/activity-log`, `/admin/monitoring`)
  - Live audit feed tracking system events (Logins, Account Creation, Password Updates, Status Changes, Ticket Merges).
  - Citizen Verification Telemetry: Monitor verification response rates, yes/no counts, and adjust dynamic system parameters (`community_reopen_threshold` and `verification_radius_km`).

Step 8: System Announcements (`/admin/announcements`)
  - Publish city-wide updates and emergency alerts broadcasted to citizen dashboards.

5. CORE INTELLIGENT ENGINES & ALGORITHMS
================================================================================

1. DUAL VISION AI ANALYSIS ENGINE (`services/aiImageAnalysisService.js`)
   - Function `analyzeImage(imageUrl)` accepts Cloudinary photo URL.
   - Stage 1 (OpenAI Vision API): Attempts call to `gpt-4o-mini` with vision prompt.
   - Stage 2 (Gemini Vision API Fallback): If OpenAI API key is missing or call fails, fetches image binary and calls Google Gemini `gemini-3.6-flash` vision model.
   - Returned JSON Structure:
     `{ detectedIssue, confidenceScore, suggestedCategory, suggestedPriority, suggestedDepartment, analyzedAt }`
   - Mapping Dictionary: Maps detected categories directly to municipal departments (e.g., Road -> Roads & Infrastructure, Garbage -> Waste Management, Water -> Water Supply).

2. MULTIVARIABLE DUPLICATE DETECTION ALGORITHM (`services/duplicateDetectionService.js`)
   - Function `findDuplicates()` executes a multi-factor search:
     1. Exact Image Match (100% Score): If uploaded image URL matches existing active complaint image URL.
     2. Distance Score (35% Max): Computes exact distance using Haversine formula against MongoDB `2dsphere` index (`location.geoPoint`).
     3. Category Synonym Normalization (25% Max): Normalizes text into canonical keys ('road', 'garbage', 'electricity', 'water', 'parks').
     4. Address & Title Text Similarity (25% Max): Tokenizes address string and computes Jaccard text overlap coefficient.
     5. Description & Title Overlap (10% Max): Token overlap across issue descriptions.
     6. Priority Signal (5% Max): Priority level match.
   - Any candidate score >= 30% is returned as a potential duplicate to prevent redundant ticket creation.

3. CITIZEN RESOLUTION VERIFICATION & COMMUNITY REOPEN TRIGGER
   - Workflow:
     Worker Resolves -> Supervisor Approves -> Citizens Notified via `/api/admin/complaints/:id/approve-resolution`.
     Nearby citizens receive verification notifications.
   - Single-Vote Guard: `CitizenResponse` model enforces unique `{ complaintId, citizenId }` compound index.
   - Community Reopen Trigger: When `stillExistsCount` >= `community_reopen_threshold` (default 2), system automatically:
     a. Updates complaint status to `Community Reopened – Supervisor Review Required`.
     b. Updates `citizenVerification.verificationStatus` to `COMMUNITY_REOPENED`.
     c. Creates a `CommunityReopenEvent` audit log.
     d. Dispatches high-priority `COMMUNITY_REOPEN_ALERT` notifications to all supervisors.
